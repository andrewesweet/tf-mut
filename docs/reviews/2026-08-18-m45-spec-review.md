# M4.5 spec review — 18 August 2026

Adversarial review of the M4.5 milestone spec (issue #71, first body), posted as a comment on
that issue. **Verdict as delivered: "not ready for an implementation agent"** — six critical
contract failures, nine major gaps; M1–M4 decisions treated as constraints.

All fifteen findings accepted, six with chosen-option modifications. Issue #71's body after
this review (revision 2) and the design correction in the same change are the disposition of
record.

## Dispositions

| # | Sev | Finding (compressed) | Disposition |
| --- | --- | --- | --- |
| C1 | CRIT | "Safety first" evaluated against an undefined program: an untested module has no mocks, so the unchanged gate refuses everything `characterise` exists for; and mocking is per provider **configuration** (aliases), not per requirement | **Accepted.** The spec now defines the **effective staged suite** — module sources plus the planned scaffold — and the provider gate evaluates it statically, pre-execution: every provider *configuration* (default and each alias) must have a planned mock, else refusal before any Terraform run. The effects gate is unchanged — mocks do not sever provisioners. The reviewer's acceptance pair is mandatory: an untested aliased-provider module characterises with no opt-in; removing one generated alias mock causes a pre-execution refusal |
| C2 | CRIT | Failing TODOs ∧ green-before-write ∧ edit-to-resume cannot all hold — the file the agent must edit can never be written; and `expect_failures` scaffolds are unverified yet executable; the referenced protocol needs `todos`/`--resume`/`--answer`, which the spec never adds | **Accepted, the reviewer's coherent protocol.** TODO and scaffold material is a **non-executable artefact class** (a distinct extension, never read by `terraform test`); `characterise` writes only the verified-green subset as executable tests. `tf-mut todos`, `characterise --resume` and `--answer` join the spec as contracted command surfaces with command-level tests. **Promotion** is the only route to executable content: an answered TODO re-synthesises, pin-verifies, then promotes; an answered scaffold verifies its `expect_failures` behaviour before promotion — unverified therefore always equals non-executable. The unsynthesizable-variable end-to-end case (write → edit/answer → resume → promotion) is mandatory |
| C3 | CRIT | Generated scenarios share implicit Terraform state (R2-4): the first apply-mode scenario creates, later ones update, and observations depend on file order — double-harvest stability pins the wrong lifecycle stably | **Accepted.** Generated independent scenarios carry **distinct `state_key` values**; a scenario-reorder-invariance fixture joins the scaffold-soundness gate. Deliberate day-2 sequences may share a key when that feature exists; not here |
| C4 | CRIT | The "#70 collector" does not close #70: `removed` bodies are named there too, and remained a blind spot (HCL) or bare refusal (JSON) while the exit gate claimed closure | **Accepted, collect option.** `removed` blocks (destroy-time provisioners are effects) are collected into both inventories in both syntaxes, alongside `check`; `moved`/`import` remain explicitly refused in both readers. Effect and provider cases for each construct in each syntax |
| C5 | CRIT | `curate` can issue false redundancy evidence from a non-authoritative population (`--since`, sampling, tier selection, exclusions, stale cache) — "never auto-deletes" does not make a false recommendation honest | **Accepted, refusal option.** `curate` requires a full, unsampled, authoritative population — the baseline-write posture — and refuses otherwise at configuration time. Cached verdicts participate only through the current cache format (stale format is already a miss); the M3 gate-table distinction (unobserved is not absent) is reused verbatim in the report |
| C6 | CRIT | The default ladder can report success with zero assertions on a zero-output module — a contract `agent-integration.md` C2 already records and the spec omitted | **Accepted.** Zero outputs at the `outputs` rung auto-escalates to `counts` and says so; a characterisation whose selected rung produced no pins may never report complete; the zero-output fixture joins the gate |
| M1 | MAJ | The new-file write binds output bytes, not the verified input snapshot: sources can change after harvest while the output stays identical | **Accepted.** Each scaffold carries the digest of the input closure that made it green (the cache key's composition reused: sources, tests, configuration, lock and module inventory, relevant environment); the commit step re-checks input digest and target absence immediately before rename; a staged closure change at the probe yields zero writes or explicit partial state |
| M2 | MAJ | The no-write `--until-dry` loop has no staged-suite seam: the generated test exists in no source tree, and discovery/cache/mutation/suggestion contracts all read source | **Accepted.** The **staged suite** is a defined overlay consumed by discovery, mutation execution, suggestion targeting and verification during the loop; staged bytes enter the cache identity so no verdict is reused across changed staged content; the mandatory end-to-end case converges without `--write` and leaves the source tree byte-identical |
| M3 | MAJ | `report-2.3.0` named but not specified | **Accepted.** Revision 2 carries the normative tables: entities (scenario, pin, todo, scaffold, curate finding), stable IDs with stated dedup keys, closed status/reason vocabularies, presence rules encoded in the published schema, redaction rules, convergence evidence, the population-authority flag, exit codes — with real engine-produced reports validated per interesting shape, and the compatibility position stated: extending a closed enum is a minor version with the consumer contract documented, not "merely additive" |
| M4 | MAJ | Shell and file contract incomplete: paths, layout, multi-file default print, collision scope, `--force` meaning, stdout ownership, and the post-path-flag position | **Accepted.** Deterministic per-scenario file naming under the test directory; default prints all files with delimiters to stdout unless a JSON reporter owns stdout (then files go to the report); collision scope is the target path set; `--force` replaces only files the provenance record marks generated-and-unmodified; post-path flags are **refused by name** — consistent with the shipped round-3 repair — and the acceptance case asserts the refusal, not merely "a case" |
| M5 | MAJ | The form-share measurement is a proxy that cannot fail its gate: no threshold, no decision, contract unchanged under every result | **Accepted.** Replaced by an **end-to-end synthesis-rate measurement** under a pinned prototype of the actual preference pipeline (defaults → mining → typed synthesis, statically evaluated) over the pinned corpus, publishing per-module executable-scenario and TODO rates — with a stated decision rule: if the median corpus module yields no executable default scenario without a TODO answer, the `--answer` batch path becomes a mandatory M4.5b deliverable and the product claim is reworded from the measured rate; otherwise it ships as specified. Either way the number can change the plan, which is what a gate means |
| M6 | MAJ | `curate` eligibility undefined once generated and human-edited assertions share files; "never deletes" conflicts with agent-integration's `curate --apply` | **Accepted.** Provenance is recorded at write time: a generated-assertion registry (IDs and content digests) accompanies every characterise write; "generated-unmodified", "generated-edited" and "pre-existing" are mechanically decided against it, and `curate`'s eligible set is the latter two plus cross-scenario redundancy. M4.5's `curate` is **report-only**; `--apply` is deferred until it earns its own write exception, and `agent-integration.md` is corrected in this change (losing-document rule) |
| M7 | MAJ | Kill-set participation assumes Terraform reports every failed assertion with stable identity when several fail in one run — unmeasured | **Accepted.** Rule-3 measurement in the slice that assumes it: one mutant failing two assertions, order reversed, both attributed. If Terraform reports fewer than all, participation for multi-failure runs is per-assertion isolation or a distinct indeterminate-participation status — never guessed |
| M8 | MAJ | Sensitivity starts too late: TODOs publish raw diagnostics and attempted values from failed pre-harvest attempts — secret-bearing artefacts outside the stated predicate | **Accepted.** Redaction applies to **every** artefact: diagnostics, attempted values, generated comments, reports, terminal, non-executable TODO files. The mandatory fixture's secret exists only in a failed synthesis diagnostic |
| M9 | MAJ | The end-of-MVP walkthrough is not falsifiable: no runner, no command-extraction rule; a hidden duplicate script would prove the binary, not the installed instructions | **Accepted.** The installed skill embeds a **machine-executable transcript** — fenced command blocks extracted in order by the gate runner from the installed file itself — and a seeded wrong flag in the skill text must turn the gate red, proving the oracle reads the instructions rather than a parallel script |

## Pattern note

Round seven, and the sharpest fact in it: **four of the six criticals were this project's own
settled rules, unapplied to the new mode** — the wrong-program question (C1), R2-4's implicit
state (C3), the gate-table's population authority (C5), and agent-integration's zero-output
record (C6). A rule earned in one program does not transfer by existing; it transfers by
being re-asked against each new program that instantiates the shape. The checklist question
gains its final clause: *which program is this evaluated against — and has every standing
rule been re-asked against that program?*
